# 006: Points link inside the exported `.bog`; the Java binder leaves the default path

Status: accepted (N5).

## Context

Until N5 a job's points reached the station through a generated Java
installer (`BactalkPointBinder_*.java`) that had to be compiled against the
licensed SDK. The native lane makes that unnecessary: a `.bog` can carry the
links itself, and the station assembler already rebases handles.

## Decision

- **The station is read as data.** `bactalk.niagara.station_points` walks the
  BACnet driver structures (network → device → `points` → proxy points with a
  `proxyExt`) and returns an inventory of ORDs, handles, BACnet objects, data
  types and units. Nothing is executed or modified. The `bacnet:*` types it
  reads are `doc-only` catalog entries until Gate G-WB confirms a real station.
- **Suggestions, never bindings.** `bactalk.niagara.pointmap` scores station
  points against job points from expanded name tokens (an abbreviation
  dictionary of the field's spellings), BACnet object type, units and device
  grouping. A candidate with no shared name token is never suggested. The
  intake UI's Normalize step shows the ranked suggestions; only rows the
  engineer confirms become `niagara_ord` on the point.
- **Write priority is explicit.** A command binding needs a priority between
  2 and 16; priority 1 and an implicit priority are refused in the UI, in the
  import route and again in the assembler.
- **Links are ordinary Niagara links in the assembled station.** Station
  assembly adds a `b:Link` in the program's input point (proxy `out` →
  `in16`) or in the proxy point (program `out` → `in<priority>`), refuses a
  target slot that is already driven, and requires every ORD to resolve. The
  project assembler takes bindings per equipment, so one station carries an
  AHU and 25 VAVs with all their links.
- **The Java point binder is emitted only for expert-lane jobs.** The JSON
  binding plan (`niagara-point-bindings.json`) stays in every deliverable set.
- **Fallback.** Without a station the export keeps writable `Inputs` and
  `Outputs` with units, ready to link in Workbench.

## Consequences

- The N5 exit is a test: the fixture station (one AHU, 25 VAVs, technician
  names like `VAV-1-01 ZN-T` and `AHU1_OAD_CMD`) exports as one linked station
  `.bog` that passes the validator with zero warnings.
- The fixture is generated by `scripts/make_station_fixture.py` from the
  documented structure; a real contractor station may differ in ways the gate
  will surface, and the parser records what it could not read as warnings.
